# سیستم مدیریت یکپارچه — ماژول‌های اعمال‌شده از سند PDF (ملاک رسمی تغییرات)

این سند فهرست ماژول‌های اعمال‌شده از سند PDF «پیشنهاد سیستم مدیریت یکپارچه شرکت ساختمانی» است که **به‌عنوان ملاک رسمی تغییرات کارفرما** تعیین شد. بخش مالی سند (پرداخت/سررسید/بدهی) و ارزیابی/KPI نیز اکنون اعمال شده‌اند.

## ۱) گردش کامل خرید: از اعلام نیاز تا انبار و تسویه

زنجیره: **انباردار اعلام نیاز می‌کند → مدیر تأیید/رد می‌کند → کارپرداز ثبت خرید می‌کند (تأمین‌کننده + مبلغ + سررسید) → فاکتور بارگذاری می‌شود → دریافت انبار → ورود خودکار به موجودی → ثبت پرداخت تا تسویه.**

- نقش **کارپرداز / مسئول خرید** (PURCHASER) — مجوز: مشاهده خرید، ثبت خرید، مشاهده انبار
- مرحلهٔ «ثبت خرید»: تأمین‌کننده (از Master Data) + تاریخ تحویل وعده‌شده (شمسی) + مبلغ کل + **سررسید پرداخت** + **شرایط پرداخت** + توضیح
- **تصویر فاکتور** (JPG/PNG/WebP/PDF): Magic Bytes + بازپردازش Sharp + مهار مسیر + Signed URL + جایگزینی نسخهٔ قبلی
- API فاکتور: `POST/DELETE /api/v1/purchase-requests/[id]/invoice` + `GET .../invoice/file`
- ویرایش سررسید/شرایط پرداخت پس از ثبت خرید: `PATCH /api/v1/purchase-requests/[id]/payment-info` (مجوز `finance.manage`)

## ۲) مالی ساده: پرداخت، سررسید و بدهی (فاز ۳ سند)

طبق سند: «ثبت شرایط پرداخت، تاریخ سررسید، وضعیت بدهی و هشدار خودکار سررسید». طراحی عامدانه ساده — بدون دفتر کل و اسناد حسابداری.

- مدل `Payment` (پرداخت روی هر خرید: مبلغ، تاریخ شمسی، روش نقدی/حواله/چک/سایر، شماره پیگیری) + مدل `Receivable` (**طلب شرکت از کارفرما**: شرح، مبلغ، سررسید وصول، باز/وصول‌شده)
- کنترل‌های سرور: پرداخت فقط روی خریدِ ثبت‌شده/دریافت‌شده با مبلغ مشخص؛ **مبلغ پرداخت ≤ مانده بدهی** (۴۲۲ برای اضافه‌پرداخت و خرید تسویه‌شده)؛ Scope کارگاه/پروژه (ضد IDOR)
- API: `GET/POST /finance/payments`، `DELETE /finance/payments/[id]`، `GET/POST /finance/receivables`، `PATCH/DELETE /finance/receivables/[id]`، `GET /finance/summary`
- **صفحهٔ «مالی»** با سه تب بدهی‌ها/پرداخت‌ها/دریافت‌ها + ۴ کارت خلاصه (بدهی کل، سررسید گذشته، پرداخت‌شده، طلب باز) + ثبت پرداخت/طلب با تقویم شمسی
- بلوک «وضعیت پرداخت» در جزئیات هر خرید (مبلغ کل/پرداخت‌شده/مانده + ردیف‌های پرداخت)
- **هشدار سررسید گذشته**: بج قرمز روی خریدهای عقب‌افتاده + فهرست overdue در خلاصه + شمارندهٔ داشبورد
- کارت‌های مالی در داشبورد مدیر/مدیر کل/حسابدار (بدهی، سررسید گذشته، طلب باز)

## ۳) نقش حسابدار / مدیر مالی (ACCOUNTANT)

- مجوزها: `finance.view/manage`، مشاهدهٔ خرید، انبار، گزارش‌ها، صورت وضعیت، حسابرسی، ارزیابی
- Scope سراسری (مالی شرکت‌محور است) — بدون مجوز عملیاتی (ثبت ورود، تأیید نیاز و…)
- صفحهٔ ورود پیش‌فرض: داشبورد مدیریت + منوی «مالی (پرداخت و بدهی)»
- حساب آزمایشی: `accountant.sa` — گذرواژه `123456`

## ۴) ارزیابی و KPI نیروی انسانی

طبق سند: «تعریف شرح وظایف، اهداف ماهانه و نمایش درصد تحقق و عملکرد هر فرد».

- **شرح وظایف** روی پروفایل هر کارگر (فرم کارگران پنل ادمین) + نمایش در فهرست
- مدل `WorkerGoal` — **هدف ماهانه** (تعداد گزارش کار) برای هر نیرو
- API: `GET /performance?month=YYYY-MM` + `POST /performance/goals` (upsert) + `DELETE /performance/goals?id=`
- **صفحهٔ «ارزیابی و KPI»**: ناوبری ماه شمسی + کارت هر نیرو (تعداد گزارش، مجموع نفرات، آخرین گزارش، نوار پیشرفت هدف و **درصد تحقق**) + **تجمیع دوره‌ای به تفکیک کارگاه** (گزارش × نفر-روز)
- مجوز `performance.view`: مدیر کل/پروژه/کارگاه، حسابدار، ناظر، بیننده — مجوز `performance.manage`: مدیر پروژه/کارگاه (تعیین و حذف هدف)

## ۵) انبار کارگاه (موجودی و گردش)

- مدل‌ها: `InventoryStock` (کارگاه × مصالح × واحد) و `InventoryMovement` (IN/OUT با دلیل)
- ورود خودکار از دو مسیر: **دریافت خرید** (PURCHASE) و **تأیید انبار ثبت مصالح** (ENTRY — ضدتکرار با `inventoryAppliedAt`)
- خروج دستی انباردار + برگشت + **حداقل موجودی** و **هشدار کمبود** (فهرست + داشبورد + اعلان)

## ۶) منابع انسانی: جابجایی نیرو با سابقهٔ کامل

- مدل `WorkerTransfer` — از کارگاه، به کارگاه، تاریخ شمسی، علت، ثبت‌کننده
- صفحهٔ «کارگران و افراد»: دکمهٔ جابجایی + سابقهٔ کامل هر فرد

## ۷) نیروی اجرایی (خوداظهاری گزارش کار)

- نقش **FIELD_WORKER** — حساب متصل به پروفایل کارگر (الزامی)
- خانهٔ نیروی اجرایی فقط یک دکمهٔ بزرگ: **«اعلام گزارش کار امروز»**
- ضدجعل: نام/کارگاه از حساب اجباری؛ فقط گزارش‌های خودش؛ حق حذف ندارد

## ۸) چک‌لیست پروژه

- مدل `ProjectChecklistItem` + الگوی پیش‌فرض ۷ آیتمی (seed تنبل)
- شیت چک‌لیست در صفحهٔ پروژه‌ها — تیک/افزودن/حذف

## ۹) هشدار درخواست بی‌پاسخ

- درخواست‌های **PENDING بیش از ۲۴ ساعت** با بج «بی‌پاسخ» + کارت داشبورد قرمز

## ۱۰) داشبورد مدیریتی یکپارچه

کارت‌های خرید (در انتظار/تأیید/خریداری + بی‌پاسخ)، کمبود انبار، گزارش کار امروز، **بدهی تأمین‌کنندگان، سررسید گذشته، طلب باز** — به‌علاوهٔ KPIهای Enterprise (میانگین تأیید، تأخیر ۲۴h، روند ۱۴روزه، عملکرد سرپرستان).
